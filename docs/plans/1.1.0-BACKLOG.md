# 1.1.0 (was 1.0.27) — backlog from the owner (2026-09-23)

Collected while 1.0.26 was in the owner's hands; each is a fix to land in
1.0.27, in the owner's words and in order of arrival.

1. **Mac: "Map background" would not switch on** — native `confirm()` is
   swallowed by the desktop WebView. Done: `askConfirm` sheet, every
   `confirm()` in the UI converted (SOS included). Commit 0d31ec7.
2. **Photo bytes held ordinary messages** after two screenshots. Done:
   LT-4 S1c, media as its own channel. Commit 73a4cdb.
3. **Saving an uploaded document gives a `.bin`**, and saving any media
   loses the original file name. Done: the UI passes the block's name as
   `?name=` and the node writes it into Content-Disposition with an
   extension the media type vouches for (`downloadFilename`); the Android
   DownloadListener only ever saw that header. Test
   `TestASavedAssetKeepsItsNameAndGetsAnExtension`.
4. **Materials tab: tapping a media item does not open it.** Done: the
   cause was `window.open()`, a no-op in the WebView (multiple windows are
   not enabled, by design). Materials rows and file cards now open media
   in the viewer and send documents to the save path (`saveAsset`).
5. **Media viewer** (everything but music) could look better, and a group
   of photos/videos should be swipeable/pageable inside the viewer. Done:
   the viewer is the room's gallery (every complete photo/video in feed
   order, from the last entries body), swipe / arrow keys / ‹ › buttons,
   "3 of 12", the caption under the picture, a floating bar on a gradient,
   a tap on the picture hides the chrome; music stays a single item.
   Pitfall found on the stand: the global `button:active { transform }`
   replaced the nav button's centring transform on press and dropped it
   from under the pointer — centred by `top` now.
6. Host log tail: a node opened by the doorbell does not start the
   ten-minute `node-log:` tail. Closed as not reproducible: on rc21 a
   doorbell-triggered open (a message from the stand, 14:04) printed both
   the `relay:` status and the `node-log:` tail. The rc15 silence had
   another cause that did not recur. That same log showed the outbox
   walking all 26 rooms every 2–3 s: every ring and every successful dial
   kicked it through kickRelaySync — fixed, the outbox wakes for a word.
7. PutMany (LT-4 S6). Done: MsgPutMany/MsgPutManyOK (19/20), all or
   nothing at the store, quiet or loud, `put_many_total` in the status;
   the node groups identical bodies per endpoint and falls back per hint
   for an hour when a relay answers "unknown message type". Relays updated.
8. **Mike (1.0.26): "notifications repeat about 30 minutes later, though
   the message was read."** Answered by his screenshot: the line is
   "Something is waiting — open to see it" — the host's nudge for a ring
   that reached a closed node. The ring was for the ✓✓ receipt on his own
   message (the relay rang for ANY item put into a push-hinted mailbox).
   Done: the quiet put (relay wire keyQuiet=19 on MsgPut; store.Item.Quiet;
   no out-of-band ring, no "waiting" for a park; parked listeners still
   notified). Receipts, fleeting presence, media bytes, media questions
   and "I moved" bundles are quiet; frames ring. Tests:
   TestAQuietPutRingsNothingAndWaitsForNobody (relayserver),
   TestAReceiptRingsNoDoorbell (node). Needs the relays updated; an old
   relay ignores the key and rings as before. Still open: WHY Mike's node
   is closed at rest (the nudge exists only for that case) — ask him what
   "While the phone is locked" says in Settings → This device.
9. The relay state file was read on every route decision — done, cached
   per file change (relaystore.go).
10. **Testers: "the PIN every time", and the face offer it invites.** Done:
    the code/face gate is off by default when a passphrase is remembered
    (`UnlockRoute.doorsApply`), a switch "Code when opening" in Settings →
    This device (bridge verbs requireCodeApplies/requireCode/setRequireCode,
    handlers 279/280).
11. **Materials, "all": the room's header vanished and nothing scrolled**
    (owner's phone, 13:22). The library panes had no `flex: 1; overflow-y:
    auto` like the log and the shelf, so a long list grew past the column
    and pushed the header out of the clipped main. Done in styles.css
    (`#files, #links, #materials`).
