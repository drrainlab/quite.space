# Состояние радиосвязи: что известно, что сломано, что не проверено

Снимок на 2026-08-02, по итогам дня работы с двумя реальными платами.
Пишется как рабочий документ, а не как отчёт об успехе: половина полезного
здесь — это отвергнутые гипотезы и ошибки, которые не стоит совершать снова.

## 1. Оборудование — что стоит на столе

| | плата A | плата B |
|---|---|---|
| модель | **Heltec WiFi LoRa 32 V3** (подтверждено: `hwModel: HELTEC_V3`) | назв. владельцем «LilyGO»; **модель не подтверждена** — в чужой базе узлов светится как `UNSET` |
| MCU | ESP32-S3 (из баннера boot ROM: `ESP-ROM:esp32s3-20210327`) | ESP32-S3 (нативный USB) |
| USB | мост **CP2102** (Silicon Labs) → `/dev/cu.usbserial-0001` | **нативный USB** ESP32-S3 (CDC) → `/dev/cu.usbmodem24EC4A307B541` |
| прошивка | Meshtastic `2.7.26.54e0d8d` (прошита нами) | Meshtastic `2.7.15.567b8ea` (была) |
| node id | `043ccd50` (71093584) | `4a307b54` (1244691284) |

Это **вторая** плата Heltec: первая (chip ID `08EAFCF61B44`) заменена
владельцем как подозрительная. Разница между ними была реальной — первая
передавала примерно в девять раз меньше в той же роли, — но причиной
отсутствия доставки она **не была**.

Имя порта не зависит от разъёма: у CP2102 оно от чипа, у нативного USB — от
MAC. Перестановка кабелей их не меняет.

### Настройки радио (одинаковые на обеих)

```
регион        RU        868.7–869.2 МГц, duty cycle 100%, до 20 dBm
                        RDEF(RU, 868.7f, 869.2f, 100, 0, 20, true, false, false)
пресет        LONG_FAST SF11 @ 250 кГц, ~2 с эфирного времени на пакет
hop limit     3
канал         pinemesh, отпечаток 56ed34ea, ключ приватный
              (Heltec слот 1, LilyGO слот 2 — номер локальный, ключ общий)
первичный     стоковый публичный, ключ по умолчанию
```

**Последнее — дефект конструкции сегмента, а не мелочь.** Частотный слот
Meshtastic считает по имени **первичного** канала, и все вторичные каналы
едут на частоте первичного. Оставив стоковый публичный первичным, мы
вещаем ровно на той частоте, которой пользуются соседи, — какой бы
приватный ни был наш вторичный канал.

### Радиообстановка

С Heltec слышно **одиннадцать** посторонних узлов (`meshtastic --nodes`),
среди них `fDaemon` (HELTEC_V4), `city17m` (HELTEC_MESH_NODE_T114),
`DIY_V1`. Это живая соседская сеть на том же диапазоне.

Платы стоят в ~2 м друг от друга. На 30 см поведение было тем же, так что
взаимная перегрузка приёмников исключена.

## 2. Насколько менялся основной протокол

**Формат Quiet Spaces на проводе не менялся вообще.** Ни один байт wire не
добавлен, не убран и не переставлен. Ни одного нового ключа, схемы,
версии или обязательного поля.

Что менялось и на каком уровне:

| изменение | уровень | видно ли на wire |
|---|---|---|
| `transports.Pacer` / `Credit` | внутренний интерфейс Go | нет |
| чтение `QueueStatus`, `Routing`, `request_id` | **чужой** протокол Meshtastic, только декодирование | нет |
| `want_ack` | бит в `MeshPacket` Meshtastic | нет, это их поле |
| `messageBudget` = 1 пакет | сколько СОБЫТИЙ пакуем в одно сообщение | формат тот же; узел на старой сборке разбирает без изменений |
| `ErrCarrierFull` | локальный поток управления | нет |
| `held`-причины в статусе реле | локальный HTTP API | нет |
| команды `radio *` | пишут в устройства Meshtastic | нет |

Единственная тонкость — `messageBudget`: он меняет **размер** наших
сообщений, но не их грамматику. Фрагментация использует ту же
`FragmentStream`, что и раньше, так что совместимость сохранена.

### 3.2 Наш, самый дорогой — **исправлен 2026-08-02** (MR-0)

**`PlanLoRaApply` выключал передатчик.**

`admin.set_config` заменяет всю `LoRaConfig` целиком: поле, которое мы не
отправили, становится нулём. `PlanSegmentApply` писал `tx_enabled = true`,
а `PlanLoRaApply` — **не писал вовсе**. Значит любая команда `radio region`
тихо выставляла `tx_enabled = false` — и печатала `✓ region set`.

Комментарий, который был написан к этой команде — «меняет только то, о чём
попросили» — **ложен на уровне протобуфа**, и это относится к любому
частичному `set_config`.

Очевидная починка — «прочитать в `LoRaSettings`, поменять поле, закодировать
обратно» — **тоже теряет данные, и молча**: структура держит десять
varint-ов, а `decodeLoRaConfig` по своему же комментарию пропускает
`override_frequency` (float). У лицензированного оператора эта частота
пережила бы баг и исчезла бы в день его «починки» таким способом.

**Как сделано вместо этого.** Изменение — это ПАТЧ ПО БАЙТАМ той
конфигурации, которую сообщило само радио. Поля, о которых эта сборка
никогда не слышала, проходят насквозь. Если байтов нет (нода ничего не
сообщила) — запись **отклоняется**, а не выполняется вслепую.

Проверка изменилась вместе с этим: поля, которые запись ИЗМЕНИЛА, доказывают,
что она легла; поля, которые она ОБЯЗАНА была сохранить, доказывают, что она
не унесла с собой ничего лишнего. Радио, вернувшееся с тем, чего никто не
просил, — теперь именованное состояние `radio_config_invalid`, и отчёт
называет поле.

Заодно закрыто то же самое в `PlanSegmentApply` (при `matchLoRa` он обнулял
`channel_num`, `tx_power` и ручную тройку bandwidth/SF/CR) и добавлен
`radio region --tx on|off` — потому что передатчик не включается как
побочный эффект другой команды, но плате, которую этот код заглушил, нужен
путь назад.

### 3.3 Про среду — подтверждено

- Соседская сеть занимает диапазон: 11 узлов.
- Мы на их частоте **по построению** (см. §1).
- **Режим ретрансляции на Heltec — `ALL`.** То есть `--quiet-neighbours`
  не лёг вообще. Раньше это было структурно невидимо: декодер возвращал
  только `Config.lora` и молча выбрасывал `Config.device`, так что ту
  запись нечем было прочитать обратно. Теперь читается.
- Роль устройства — `CLIENT`.
- Duty cycle нас не ограничивает: у RU он 100%, а не 10% как у EU_868.
- Платы **слышат друг друга напрямую**: 0 хопов, SNR 6 дБ, проверено
  чистым `meshtastic --nodes` без нашего стека.
- Наши пакеты **доходят и расшифровываются**: сырой пробник на порту
  Heltec поймал `from=4a307b54 ch=1 port=256 enc=false len=94`.
- Очередь радио **никогда не переполнялась**: `refused=0`, свободно 12–16
  из 16. Гипотеза, ради которой делался бэкпрешер, **не подтвердилась**.

## 4. Тесты

### 4.1 Автоматические (без железа)

`transports/pacing_test.go`
- носитель без `Pacer` остаётся неограниченным (обратная совместимость);
- «нет места сейчас» ≠ «не могу сказать»;
- сообщение предлагается целиком или никак.

`kernel/sync/budget_test.go`
- радио-носитель получает бюджет в один пакет; неограниченный — прежний.

`transports/meshtastic/firmware_test.go`
- boot-баннер называет чип и **не** называет плату; тишина — не чип;
- рецепт прошивки: factory-образ на 0x0, littlefs по смещению **из
  манифеста релиза**; незнакомый раздел — отказ, а не правдоподобное число;
- чип **сужает** список вариантов и никогда не выбирает из него;
- команды прошивки: сначала стирание, каждый файл на месте;
- опечатка в имени региона — ошибка, а не `UNSET`;
- регион меняет только регион;
- `QueueStatus` читается из поля 11; кредит = сообщённое минус отправленное
  с тех пор; отказ прошивки считается отказом;
- `want_ack` доходит до wire; повторы **не** объявляются подтверждением;
- вердикт прошивки засчитывается только для **наших** пакетов; запрос
  маршрута — не вердикт; без `want_ack` счётчики молчат;
- частотный слот и режим ретрансляции пишутся; запрос одного режима не
  тащит за собой пустую запись LoRa.

`transports/meshtastic/patch_test.go` — сердце MR-0
- **запрос одного региона оставляет байт-в-байт всё остальное**, включая
  `tx_enabled`, float `override_frequency` и поле из прошивки новее этой
  сборки (тест, который был бы красным до MR-0);
- ноде, ничего не сообщившей, не пишут вслепую, и отказ называет ставку;
- проверка ловит поле, которое запись СТЁРЛА, а не только то, которое
  она поставила;
- та же конфигурация в другом порядке и без умолчаний — не расхождение
  (устройство перекодирует по-своему, сравниваются смыслы, не байты);
- отсутствующее поле можно выставить впервые; выставленное в умолчание
  не оставляет следа;
- пустое подсообщение — это ответ, а не молчание;
- поле неожиданной формы останавливает всю запись.

`transports/meshtastic/snapshot_test.go`
- снимок переживает файл точно, включая нечитаемое этой сборкой;
- восстановление возвращает передатчик и всё, что было; float честно
  назван невосстановимым, а не пропущен молча;
- настройка, которой в снимке не было, уходит в умолчание;
- неизменившееся радио не пишется вообще;
- дрейф называется по полям; исчезнувшее подсообщение — самая громкая
  строка диффа, а никогда не захваченное — не дрейф.

`transports/meshtastic/serial_test.go`
- молчащее устройство завершает чтение, а не висит;
- **подключённый** линк переживает тишину (регрессия §3.1 №2);
- дедлайн — на вызов, не глобальный;
- повторяется только «промолчало», но не «нет такого пути» и не «занято».

### 4.2 Живой прогон — процедура

```bash
# по узлу на плату, ОБА с --no-lan и без реле, иначе проверяется не радио
go run ./cmd/terminal ui --passphrase P --data /tmp/a --name alice \
  --no-lan --no-browser --port 8801 --mesh serial:<A> --mesh-channel <slot A>
go run ./cmd/terminal ui --passphrase P --data /tmp/b --name bob \
  --no-lan --no-browser --port 8802 --mesh serial:<B> --mesh-channel <slot B>
```

Создать пространство, пригласить, отправить сообщение, смотреть
`/api/status`:

```
tx rx                      сколько отдали радио / получили
acked gave_up outstanding  вердикты ПРОШИВКИ по надёжным отправкам
queue_free queue_max       очередь радио, как она сама её видит
refused                    сколько пакетов прошивка НЕ взяла
```

**Признак здоровья:** `acked` растёт, `gave_up` и `outstanding` низкие,
`refused` = 0, доля дошедшего заметно выше 15%.

**Проверять перед каждым прогоном** (после §3.2 — обязательно):

```bash
go run ./cmd/quiet-radio --radio serial:<порт>   # tx должен быть enabled
```

## 5. Что делать дальше, по порядку

1. ~~Починить `PlanLoRaApply`~~ · ~~расширить проверку после записи~~ —

3. **Stage A — базовая линия носителя.** Две платы, 2 м, однокадровая
   полезная нагрузка, ≥100 пакетов на режим:
   `LONG_FAST/ALL`, `LONG_FAST/LOCAL_ONLY`, `MEDIUM_FAST/LOCAL_ONLY`,
   `SHORT_FAST/LOCAL_ONLY`. Критерий выхода — двоичный:

   ```
   доставка однокадровых до приложения  ≥ 98%
   refused                              = 0
   outstanding                          возвращается к базовой линии
   необъяснённых разрывов               нет
   ```

   Если остаётся ~15%, причина **ниже фрагментации** — serial-сессия,
   отображение каналов, идентичность пакетов или обработка входящих. Это
   гейт, который решает, начинать ли слой Radio Transfer вообще.
4. Только потом — частотный слот и другой пресет.

**Перед каждым прогоном:**

```bash
go run ./cmd/quiet-radio --radio serial:<порт>   # tx должен быть enabled
```

**И снимок известно-хорошего состояния**, чтобы «а как было до этого» больше
никогда не оставалось без ответа:

```bash

go run ./cmd/quiet-radio --radio serial:<порт> --diff

```
