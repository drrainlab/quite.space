# 1.1.1 — a photo is its own channel, and the doorbell rings for words

There is no published 1.1.0. Its tag stands on a commit whose CI run under
the race detector flagged a test — a test that read a log without the
runtime's lock while the doorbell lane applied items — and the release
workflow refuses a commit whose CI is red, as it should. A tag is never
moved; the fix ships as the next patch. 1.1.1 is 1.1.0 with that test
corrected and nothing else.

**A photo no longer stands in front of a word.** Sending two screenshots
and then a message left the message waiting: the photo's bytes rode in
the same bundle as its card, the bundle was big, and everything to that
person queued behind the upload — to seven mailboxes at once, because a
device with no stated route is guessed at every official relay. Now the
card and the words go on the express lane, the bytes go apart on the bulk
lane, and bytes never go to a guessed mailbox at all: the frames do, and
the bytes wait for a stated route or for the recipient's own request.

**Files keep their names, and Materials opens things.** A saved document
used to land as `asset-<hash>.bin` and a saved photo lost its name: the
node now names the download after the block, with an extension the media
type vouches for. Tapping a photo or a file in Materials — or "open
original" on a file — did nothing on a phone (the WebView opens no new
windows, by design): media opens in the viewer, documents go to the
phone's save path.

**The viewer is a gallery.** Open one photo and the room's photos and
videos are all there: swipe or use the arrows, a counter, the caption
under the picture, a tap to hide everything but the picture. Music is
unchanged.

**A receipt no longer rings anyone's doorbell.** A tester saw
"Something is waiting — open to see it" half an hour after reading a
message: the relay rang for any item put into a mailbox, and the item was
the ✓✓ on his own message. Receipts, presence, media bytes and questions
about media are now put quietly — stored and served as before, but the
doorbell rings and a phone is told "something is waiting" only for words
and pictures. Relays carry one added key on the put; older relays ring as
before until updated.

**One round trip for a room.** A word for four people at one relay used
to be three puts in series; the relay now takes one body for many
mailboxes in one round trip (PutMany), all or nothing, and a relay that
has not learned the verb is asked once and served the old way for an hour.

**The outbox no longer walks every room on every ring.** Every doorbell
ring and every successful dial used to wake the sending pass over all
rooms, so a phone with many rooms ran a full pass every two or three
seconds all day for nothing. The pass wakes for a word, for a return to
the foreground, for a media request, and for its own retry — and for
nothing else.

**Smaller things.**
- The node reads a room's media manifests from disk only when it has
  something to send, not on every pass.
- The outbox log line says where a pass's time went (lock, preparation,
  planning, sending) — and that line named the last mystery: the relay
  state file was read and parsed on every route decision, hundreds of
  times a pass on a phone with many rooms. It is read once per change now.
- On the Mac, "Map background" would not switch on and SOS did nothing:
  the desktop WebView swallows the browser's native confirm dialog. Every
  confirmation is a sheet in the page now.

**The code is not asked for every time.** Testers were typing their code
at every return and being offered their face for it. With a remembered
passphrase Quiet now opens on its own; *Settings → This device → Code when
opening* turns the code (or face) back on for anyone who wants that
second wall — off by default. Without a remembered passphrase the code or
face remain the only way in, as before.

Relays: updated (the quiet put and PutMany); an older relay keeps working — it rings for everything and takes one put at a time, as 1.0.26 did.
