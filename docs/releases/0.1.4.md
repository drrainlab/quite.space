# 0.1.4 — the phone opens again

```
   ·  ✦   ·        ╭──────────────╮       ·   ✦
 ✦    ·      ·     │  0 . 1 . 4   │  ·        ·
   ·    ✦          ╰──────────────╯     ✦   ·
```

One fix, and it is the only reason this release exists.

**📱 0.1.3 crashed on Android after every correctly typed code.** You
paired, you set four digits, you typed them right — and the app fell
over, every launch. The door opened; the floor gave way. The cause was a
missing manifest permission on the new face-unlock question, which is
asked on every successful unlock. Reported within hours; reproduced on
an emulator in one pass; fixed at the root and fenced so that no
biometric question can ever take an unlock down again.

**Nothing on your phone is lost.** Update over 0.1.3, type your code, and
you are in. Your pairing, your code, your spaces — all still there; only
the crash is gone.

Also said plainly, because 0.1.3's note was not: **the name-and-four-
digits first run is desktop-only for now.** The phone still starts with a
passphrase and offers four digits one step later. It catches up next
release.
