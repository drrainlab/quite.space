# 1.0.3 — the starfield is back, and so are Settings

A fix release, the day after 1.0.2, for what the first phone taught us
within an hour: **Settings would not open, and creating a space
stumbled on its last step.**

**What happened.** The sky (the shared drawing) and the starfield (the
background) each declared a module named `SKY`. Every asset script is a
classic script sharing one global scope, so the second one to load — the
starfield — failed at parse time and silently never ran. Settings asks
the starfield for its mode and died there; on a phone the last step of
creation ran into the same call. No data was touched: rooms, messages
and skies made on 1.0.2 are intact.

**What changed.** The drawing module has its own name, and the build
now refuses the whole class of mistake — a harness reads the script
order and fails on any top-level name declared by two files.

Nothing else moved. Everything 1.0.2 announced — the familiar shell,
Files and Links, the icons, the sky itself — is exactly as described
[there](1.0.2.md).
